# Learnings

Only project-specific findings belong here. Add new entries when evidence changes a decision or prevents repeat work.

- **2026-10-22 — Scale type and HUD footprint separately.** A literal 200% canvas at 1024×700 covered most of the pickable battlefield and let the minimap overlap selection. Capping the panel footprint at 150%, scaling text the remaining amount, and scrolling commands preserved the board in local captures at both target windows. Human readability on the signed download remains owed. See the [interface review](../docs/interface-review/qa.md).

- **2026-10-21 — Check population and network together.** The 50-entity paced local benchmark measured tick cost but not packet behavior; the earlier impaired full match started with four entities. A disposable copy of the deployed image with only a test-only population seed let native macOS/Linux clients compare the same ordered commands under baseline, 100 ms and symmetric 150 ms/loss profiles without changing the live service. Keep the sampled RTT and packet-drop counts distinct from configured impairment. See [current QA](../docs/multiplayer-qa-2026-10-21.md).
- **2026-10-21 — Start reconnect grace when play starts.** A participant can wait more than 60 seconds for a second code. The first owner's GUI match expired at tick 0 because the waiting slot's last-seen timestamp was reused at play start. Refresh both slots when the authority enters `playing`, and preserve the 60-second no-result policy after that point. See [remote QA](../docs/multiplayer-remote-qa-2026-10-20.md).
- **2026-10-21 — Rotate invites without losing slot or replay ownership.** The original unique player binding blocked a returning installation after its old code was revoked. Restrict uniqueness to active bindings, retain historical audit rows, keep a verified replacement in the same match slot, and authorize retained replay through its bound installation ID. The owner's first join exposed the database issue before any match. See [remote QA](../docs/multiplayer-remote-qa-2026-10-20.md).
- **2026-10-20 — Refresh the match process after changing preview admission.** An internal cross-OS join still received `match_disabled` immediately after the Golden Frijoles preview flag reached on version 10. Restarting the one-room match process picked up the served value; a bad-code probe then returned 401. After the smoke, set preview off, restart, and verify a current-version join returns 403. See the [remote QA](../docs/multiplayer-remote-qa-2026-10-20.md).
- **2026-10-20 — Benchmark the deployed CPU quota and refresh the client simulation hash.** The unchanged 162-entity back-to-back gate failed at 0.75 CPU even after route and visibility optimization, then passed at the deployed 1.0 CPU cap with the same final state hash. The match client's `alpha_config.gd` hash must be updated whenever `skirmish.gd` changes; otherwise a source-matched local client gets `version_mismatch` before join. See the [remote QA](../docs/multiplayer-remote-qa-2026-10-20.md).
- **2026-10-16 — Cache static occupancy for scale, then preserve it across restore.** Repeated building-footprint scans made the 32×32 route p95 68.041 ms in the first crowd run. A cache lowered it to 3.117 ms in the final debug matrix, within the declared 6 ms budget; save restore rebuilds the cache. This does not solve fighter overlap or low-end-device performance. See the [foundation benchmark](../docs/simulation-benchmark-2026-10-16.md).
- **2026-10-16 — Keep save and telemetry lifecycles separate.** The v1 local save stores canonical match state and the match ID but excludes invite credentials and the funnel outbox. Resume retains the ID, emits no new start and refuses a completion already recorded in the outbox. Version/content mismatches preserve the file with an explicit error. See [ADR 003](../docs/architecture-decisions/003-simulation-contract.md).

- **2026-10-16 — Preserve the prototype, then formalize its seams.** The current Godot match already uses validated commands, a fixed logical tick, snapshots and repeatability checks, but `game/skirmish.gd` also hardcodes the one-resource economy, map, AI and faction values. Broader four-age content should follow a versioned command/state/content and save/replay contract, with representative crowd and cross-platform evidence before multiplayer model selection. See the [architecture review](../docs/architecture-review-2026-10-16.md).

- **2026-10-13 — Start with a measured funnel.** The game has no playable build, so there is no observed retention baseline. The 15% later-day match completion goal is a hypothesis to revisit after the first mature cohort. See [North Star](00-strategy/north-star.md).
- **2026-10-13 — Aggregate by player before reporting retention.** Golden Frijoles `telemetry_event` inputs count raw event occurrences. The agreed North Star needs distinct players and a later-day condition, so compute those values from identified game events and send the resulting readings through `external_push`.
- **2026-10-13 — Keep products separate.** Golden Frijoles CLI commands act on a selected product. This repo belongs to `aomx`; verify the active product before any future push or key operation.
- **2026-10-14 — Fixture measurement can precede the game.** The local Node contract, audit and cohort checks run without a game runtime, but rendered Godot and real outcome checks still require one. The aomx console has no first event or observed baseline.
- **2026-10-14 — External input pushes are append-only.** The Golden Frijoles SDK deduplicates a day and reports a mismatched retry without overwriting it. Late cohort corrections therefore need a reviewed backfill process before real readings are pushed.
- **2026-10-14 — Eligibility must carry across events.** A flag-off match start cannot support a later public completion when the flag turns on; acceptance must trace back to an accepted open and start. An unobserved quiet day also cannot be reported as a zero without a coverage marker.
- **2026-10-13 — Engine decision is provisional until a playable test.** At openage commit `3da21ab`, movement and rendering foundations exist, but gathering and construction are not live game systems; the local build stopped during CMake configuration at missing `toml11`. Use Godot for the first original-content prototype and revisit with measured play and performance evidence. See [ADR 001](../docs/architecture-decisions/001-engine-selection.md).

- **2026-10-14 — Godot supports the first local complete match.** A fixed-tick 20×20 skirmish passed economy, combat, replay and win/loss/draw checks on Godot 4.7.2. At 12 units, route attempts averaged 0.5440 ms and ticks 0.0491 ms on an M2 Max; crowd movement can overlap and release-build performance remains unmeasured.
- **2026-10-14 — A return open must be a new event.** Reusing the first `game_opened` on every launch hides the later-day return stage. Reuse on same-day restart and queue a new open on a later UTC date; block dependent uploads behind unresolved earlier receipts.
- **2026-10-14 — Validate a Pod Report before pushing it.** The project-scoped Golden Frijoles setup mentions an outcome report, but kit 1.9.2 does not install `pod-report.mjs`. The provider's own script can read an aomx checkout, yet its `git log -S 'status: shipped'` search matches README guidance comments and falsely reports the two unshipped master epics as shipped. The dry run was kept local; do not push that artifact until the provider script parses actual frontmatter status transitions.
- **2026-10-14 — The database choice changed at provisioning.** Supabase Free refused a third active project even in a new organization. The owner chose an isolated Postgres container on the existing Oracle VM, with a separate private OCI backup bucket. Keep VM limits, network separation and disposable-restore evidence as alpha release gates.
- **2026-10-14 — A macOS export requires the matching template and ETC2/ASTC import.** Godot 4.7.2 exported the first versioned preview ZIP only after installing its checksum-verified macOS template and enabling the ETC2/ASTC texture setting. An itch.io Draft page and Butler CLI can be prepared without issuing participant access.
- **2026-10-14 — Check container network and client versions during recovery rehearsal.** Docker did not publish the Postgres loopback port when its only network was internal, and the VM's `pg_dump` 16 could not dump Postgres 17. A separate aomx operations bridge and the database container's matching tools made the off-project backup and disposable restore work without opening the database publicly.
- **2026-10-16 — Keep the command HUD below the fixed board.** At 1280×800 and 1024×700 with 120% board zoom, the 20×20 board remains selectable above a bottom Control bar. A compact district summary and sync count keep the status text inside that bar, including in a local preview-channel window with invite and support controls.
