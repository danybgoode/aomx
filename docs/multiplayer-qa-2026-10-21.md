## Playable population-cap network matrix

The disposable match container ran the unchanged `aomx-match:0d29ed3` Godot/Node image at its live 1 CPU / 768 MiB cap. A read-only, test-only worker overlay seeded 23 alternating melee/ranged fighters on each side in the 28×28 La Roma map, in addition to the two workers and two command posts: **50 entities, 25 owned by each side**. Map content, four resources, fog, rules, seed 1 and network protocol matched the live service. The container had an in-memory invite store and a 150-tick QA time limit; its `match_time_limit` no-result is a test stop, not a gameplay victory. It never replaced or modified the live match container.

Official Godot 4.7.2 native macOS on the owner's Apple M2 Max and native Linux ARM64 on the Oracle VM joined with distinct temporary codes. Each side sent the same ordered 10-command burst, `hold` on its starting worker, in every profile. Each restored every received participant state with `MultiplayerState.restore_for_side`, verified 25 own entities, accepted all 10 orders and reached tick 150. Both clients, and all three profiles, reported canonical hash `7c1892b94875d2ee370617f8e5e732b19b398da3dc59a8ba277c2cabf2fa27e4`. No state-restore error or first divergent tick was observed. The comparison checks received authoritative state and terminal hash; a fogged client does not independently re-simulate the full canonical hash. The visible entity count differed by fog, as expected.

The RTT values are end-to-end HTTP calls from the Mac through its SSH tunnel, including host work. Their baseline variance masks the imposed 100 ms difference at p50; p95 rose under loss. The native clients shared the same relay setup for both directions in the impaired profiles. The scripted HTTP clients additionally sent 10 distinct fighter `hold` orders per side under each profile; all were accepted, both sides agreed at tick 150 and no same-tick server hash mismatch was seen. Their cross-profile final hashes differed because order issuance occurred at different ticks. The native fixed worker-order stream gives the direct cross-profile comparison above. TCP retransmission makes observed packet loss stochastic; the live full-match relay recorded more drops than the short matrix runs.

The matrix demonstrates bounded 50-entity command and reconciliation behavior, not competitive readiness, many simultaneous rooms or a public retention result. The scripted fixture's 150-tick time limit does not exercise the full match's terminal/replay path; the separate live Restricted full matches above cover that path. The existing paced 500-order/300-tick local benchmark and unchanged 162-entity stress gate cover a larger order burst and tick budget separately.
